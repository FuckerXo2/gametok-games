Docs

Your game stays on your own HTTPS site. GameTok shows it in its feed, in a frame, and one script — bridge.js — lets it ask who's playing, report scores, and pair players for multiplayer. Your server checks players with the GameTok API before trusting them.

How it fits together

Your game

Any web game (HTML5, Canvas, Phaser, Three.js, Unity WebGL, Godot…) on your own HTTPS address. It loads bridge.js and calls GameTok.*.

The GameTok player

The feed and game pages on gametok.co (and the GameTok app). It frames your game, pauses and resumes it, and answers GameTok.init() with the signed-in player.

Your server (optional)

Holds your secret API key. Checks player sessions, saves progress against the player's id, runs multiplayer rounds and reports results.

Updates are instant: GameTok loads your hosted URL, so every time you deploy, players get the new version.

Quick start

  1. Sign in at games.gametok.co/dashboard, choose your username and accept the Developer Agreement.
  2. Add the bridge to your game's index.html: 
    <script src="https://gametok.co/bridge.js"></script>
  3. Allow GameTok to frame your page (see below) and deploy.
  4. Try it as a draft: in the dashboard click + New Game, paste your URL and tick Save as a draft to test first. It opens in the private test player.
  5. Go live: click Go live in the test player or on the game's page. If the automatic checks pass, it's in the feed at gametok.co/game/<id>.

Allow GameTok to show your game

GameTok shows your game inside a frame on https://gametok.co (and the test player on https://games.gametok.co). Your page must not send X-Frame-Options: DENY or SAMEORIGIN. If you send a Content-Security-Policy, include:

Content-Security-Policy: frame-ancestors 'self' https://gametok.co https://games.gametok.co

Publishing

Three ways, all ending in the same automatic checks:

  • Dashboard: + New Game → your hosted URL, or upload a single self-contained index.html.
  • API: POST /api/publish with an API key (see reference).
  • AI agent: give Claude Code, Cursor or similar the prompt on the home page; it follows skill.md.

Publishing again with the same title updates your game. Re-check a live game any time from its Checks tab.

Test mode

Drafts are private: they aren't in the feed, search or your public profile, and their GameTok page isn't public. You play them in the test player (games.gametok.co/sandbox/?game=<id>) — the real GameTok player in TEST mode:

  • GameTok.init() returns a test player (id t_…) and a test session.
  • Every message between your game and GameTok is shown in a log.
  • An integration checklist ticks itself: bridge loaded, player requested, session verified by your server, score submitted.
  • Buttons send pause/resume so you can check your game handles them.

Make drafts with a test key (gtk_test_…) — anything it publishes is a draft and it can never change a live game — or with the dashboard's Save as a draft. When it works, click Go live.

bridge.js reference

Load it from https://gametok.co/bridge.js (never a copy: it gets fixes). Outside GameTok it stays dormant and your game works normally. Promise-returning calls reject with an Error that has a .code (see Error codes).

Player identity

Players are already signed in to GameTok, so your game doesn't need its own login.

const { player, session, mode } = await GameTok.init()
// player = { id: "p_3QmZ…", name: "Tolu", avatar: "https://…", guest: false }
// Send `session` to your server and verify it there before trusting `player`.
  • player.id is a pseudonym for your game only. The same player always gets the same id in your game and a different one in every other game. Use it as your user id (progress, unlocks, saves).
  • Guests: players who aren't signed in get guest: true, the name "Guest" and an id tied to their device.
  • Never trust the browser. Anyone can edit game code. Your server must check the session:

Authorization: Bearer gtk_live_…        (gtk_test_… in the test player)
{ "session": "<session from the game>" }

Multiplayer

GameTok runs the lobby; your server runs the gameplay. Players create a match and share its six-letter code, join by code, or quick-match with someone waiting in your game. When every seat is filled the match starts; your server plays the round (over your own WebSocket, etc.) and reports who won. Matches have no stakes.

// In the game
const m = await GameTok.match.quick({ seats: 2 })     // or match.create({ seats }) / match.join(code)
showCode(m.code)                                      // friends can join with GameTok.match.join(code)
const stop = GameTok.match.onUpdate(async (m) => {
  if (m?.status === 'playing') connectToMyServer(m.id, await GameTok.session())   // your server checks the session
  if (m?.status === 'done') showWinner(m.winner)
})
CallResult
GameTok.match.create({ seats })A new match for 2–4 players with a code to share.
GameTok.match.join(code)Join by code. Starts the match if it fills it.
GameTok.match.quick({ seats })Join the oldest open quick match in your game with a free seat, or open one.
GameTok.match.current()Your open or playing match in this game, or null.
GameTok.match.leave()Before the start you leave the match; after it you're marked as left (your server decides the result).
GameTok.match.onUpdate(fn)Calls fn(match) whenever it changes. Returns unsubscribe().

A match is { id, code, status, seats, players: [{ id, name }], me, winner, result, createdAt, startedAt, endsAt, mode }. status is open, playing, done, cancelled (never filled within 15 minutes) or void (no result within 2 hours of the start). A player can be in one open/playing match per game.

Reporting the result (your server only)

Only your server can settle a match: it needs your API key and a signature with the results secret shown when you created that key. A phone can never post a result.

// Node 18+
const crypto = require('crypto')
const API = 'https://gametok-backend-267787411422.us-central1.run.app'

async function reportResult(matchId, winner /* player id or "draw" */) {
  const auth = { Authorization: `Bearer ${process.env.GAMETOK_API_KEY}` }
  const { match } = await (await fetch(`${API}/api/developer/matches/${matchId}`, { headers: auth })).json()
  const path = `/api/developer/matches/${matchId}/result`
  const body = JSON.stringify({ winner })
  const timestamp = String(Math.floor(Date.now() / 1000))
  const bodyHash = crypto.createHash('sha256').update(body).digest('hex')
  const signature = 'v1=' + crypto.createHmac('sha256', process.env.GAMETOK_RESULTS_SECRET)
    .update(['POST', path, timestamp, match.nonce, bodyHash].join('\n')).digest('hex')
  const res = await fetch(API + path, {
    method: 'POST',
    headers: { ...auth, 'Content-Type': 'application/json', 'X-GameTok-Timestamp': timestamp, 'X-GameTok-Signature': signature },
    body,
  })
  return res.json()   // { match: { status: "done", winner, … } }
}

Settled once: sending the same winner again returns the same match; a different winner afterwards is 409 ALREADY_SETTLED. Check each player's session (sessions/verify) when they connect to your server so you know the ids in the match are really them.

API keys

Create keys in Dashboard → Settings → API Keys. Each key and its results secret are shown once; GameTok stores only a hash of the key. Revoke a key there at any time — it stops working immediately. Keys can't accept the Developer Agreement or create other keys; that needs you, signed in.
